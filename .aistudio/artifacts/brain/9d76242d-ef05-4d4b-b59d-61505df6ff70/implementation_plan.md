# منصة متابعة إدارة PHY BU (Hikvision / Velasea / AMG) — مصر
## المرحلة 0 ولوحة التشغيل والمتابعة التنفيذية فوق Odoo

خطة معمارية وتنفيذية شاملة لبناء منصة المتابعة المستقلة لإدارة PHY BU (المسؤولة عن توكيلات Hikvision وVelasea وAMG في جمهورية مصر العربية)، كطبقة قراءة ذكية واستكشاف للمرحلة 0 دون أي كتابة على دفاتر Odoo الرسمية، مع إدارة البيانات المضافة محلياً (وعود الدفع، ملاحظات التحصيل، جدولة الموردين، عمر المخزون وتصنيف الفواتير المختلطة).

---

### قرارات المستخدم المعتمدة والمرجعيات الأساسية

> [!IMPORTANT]
> **مبادئ التصميم والمحددات الحاكمة المعتمدة:**
> 1. **قراءة فقط (Read-Only):** لا كتابة إطلاقاً في Odoo في الإصدار الأول لحماية الدفاتر المحاسبية.
> 2. **فلترة على مستوى البند (Line-level Filtering):** عزل مبيعات ومشتريات ومخزون الإدارة بالبراند على بنود الأوامر والفواتير (`sale.order.line`, `account.move.line`) لمنع خلط الفواتير المشتركة.
> 3. **الدولار كعملة تقرير أساسية (USD Reporting):** تحويل وعرض كافة المبالغ بالدولار الأمريكي مع بيان العملة الأصلية وسعر الصرف، وعرض المبالغ شاملة الضريبة 14% مع إبراز الصافي بدقة.
> 4. **التعامل مع الفواتير المختلطة:** تطبيق الخيار (ب) بعرض الفاتورة التي تحوي بنود الإدارة مع وسم صريح "فاتورة مختلطة" ونسبة مساهمة بنود البراند، دون تزوير أو اقتطاع تعسفي.
> 5. **المرحلة 0 المتكاملة:** المنصة توفر لوحة عمل تشغيلية متكاملة مدعومة ببيانات نموذجية واقعية للتوكيلات الثلاثة، مقترنة بمحرك استكشاف واتصال حي بقاعدة أودو (`eelaf-master-21952014`) لاكتشاف أسماء الحقول المخصصة ونسبة جودة التمييز.

### 1. نظرة عامة والهدف التشغيلي (Overview & Core Concept)

* **ما تقدمه المنصة:** طبقة استخبارات أعمال ومتابعة تشغيلية يومية لمدير إدارة PHY BU (تامر) وفريق مبيعات الإدارة، تجيب فور فتحها عن: "ما الذي يتطلب تدخلي الفوري اليوم؟" (التحصيلات المتأخرة، وعود السداد المنقضية، أوامر التوريد المعلقة، المخزون الراكد، ومدفوعات الموردين الحرجة).
* **الفئة المستهدفة:** مدير الإدارة (صلاحيات كاملة على الأرقام والهوامش والتسعير)، مسؤولو مبيعات الإدارة (متابعة أوامرهم وعملائهم وتحصيلاتهم)، مع عزل تام عن باقي إدارات الشركة.
* **القيمة المضافة الفريدة:** حفظ ما لا يملكه Odoo محلياً: سجل تاريخ وعد الدفع (`Promise Date`)، المسؤول عن المتابعة، الجدولة التقديرية للموردين، وقواعد احتساب أعمار المخزون والديون.

  - مساحات محايدة هادئة وراقية (Slate / Crisp White / Subtle Hairline Dividers).

  - القرمزي (`#DC2626`): تأخر سداد / وعد منقضٍ / صنف راكد > 90 يوماً / أمر متوقف.

### 3. الوحدات التسع للشاشات والوظائف

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                       منصة متابعة إدارة PHY BU (مصر)                         │
├───────────────┬─────────────────────────────────────────────────────────────┤
│ 1. الرئيسية   │ مؤشرات اليوم الحرجة: متأخر التحصيل، استحقاق المورد، الأوامر  │
│ 2. التحصيلات  │ فواتير العملاء، أعمار الديون، وعود الدفع، ملاحظات المتابعة   │
│ 3. الموردين   │ فواتير Hikvision/Velasea/AMG، مواعيد الاستحقاق، جدولة الدفع │
│ 4. الأوامر    │ دورة حياة الأوامر (العرض -> التعميد -> التسليم -> الفوترة)   │
│ 5. المخزون    │ الكميات، عمر الصنف (FIFO)، الأصناف الراكدة، سجل الحركات     │
│ 6. عملاء مصر  │ سجل عملاء التوكيلات، أرقام التواصل، إجمالي المشتريات، المديونية│
│ 7. الفريق     │ أداء مناديب الإدارة vs مبيعات التوكيلات من خارج الإدارة     │
│ 8. التنبيهات  │ قائمة الإشعارات الذكية والعتبات الاستثنائية                  │
│ 9. استكشاف Odoo│ أداة المرحلة 0: اختبار الاتصال، كشف الحقول، فحص جودة العينات │
└───────────────┴─────────────────────────────────────────────────────────────┘
```

#### تفاصيل الوحدات:
1. **اللوحة الرئيسية (Daily Command Center):**
   - 4 بطاقات قياس عليا: إجمالي التحصيلات المتأخرة، المدفوعات المستحقة للموردين هذا الشهر، أوامر قيد التنفيذ المعلقة، قيمة المخزون الراكد (>90 يوم).
   - جدول التدخل السريع: قائمة بـ 5 مهام حرجة اليوم (فواتير كسر عملاؤها وعد الدفع، شحنات بضاعة تجاوزت 15 يوماً دون فوترة).
2. **التحصيلات وإدارة الديون (Collections & AR Aging):**
   - تصنيف الديون بشرائح: (الحالي، 1–30 يوم، 31–60 يوم، 61–90 يوم، أكثر من 90 يوم).
   - جدول الفواتير مع تحديد: رقم فاتورة أودو، العميل، البراند، القيمة بالدولار (شاملة وقبل الضريبة 14%)، المتبقي، تاريخ الاستحقاق.
   - حقول المنصة التفاعلية: تعديل تاريخ وعد السداد (`Promise Date`)، تسجيل الملاحظات وتحديث حالة التواصل الفعلي.
   - مؤشر الفواتير المختلطة مع حاسبة النسبة التناسبية للبند وقيمة الفاتورة الكاملة.
3. **مدفوعات الموردين (Supplier Payables & AP):**
   - فواتير الاستيراد والمشتريات لشركات Hikvision / Velasea / AMG.
   - تتبع تواريخ الاستحقاق مع أداة محاكاة وجدولة السيولة النقدية المطلوبة أسبوعياً.
4. **أوامر الإدارة (Order Operations & Pipeline):**
   - خط زمني تفاعلي لكل أمر من مرحلة العرض (Quotation) إلى التأكيد والتسليم والتسوية.
   - فلترة وتنبيه على: "أمر مؤكد لم يُسلّم > 14 يوم"، "أمر تم تسليمه ولم يُفوتر > 3 أيام".
5. **المخزون وحركات الأصناف (Inventory Aging & Movements):**
   - بطاقات الأصناف مع رقم القطعة (SKU)، الوصف، البراند، الكمية المتوفرة بالمخازن المصرية.
   - احتساب عمر الصنف وفق أول دخول للدفعة (Stock Aging).
   - وسم الأصناف الراكدة (Stagnant) التي لم تشهد حركة خروج خلال عتبة محددة قابلة للتعديل.
   - سجل تفصيلي لحركات الدخول والخروج مع ربطه برقم إذن المخزن (`WH/IN`, `WH/OUT`).
6. **قاعدة عملاء مصر (Egypt BU Customers):**
   - دليل العملاء المستهدفين لبراندات الإدارة، هواتف مسؤولي المشتريات، المدينة، ومسؤول الحساب بالإدارة.
   - إحصائيات سريعة للعميل: تاريخ آخر شراء، متوسط فترة السداد، إجمالي المشتريات التراكمية، وموقفه الائتماني.
7. **لوحة الفريق والمبيعات (Sales Reps & Cross-BU Performance):**
   - متابعة مبيعات مناديب الإدارة الأساسيين.
   - رصد استثنائي دقيق: مبيعات أصناف Hikvision/Velasea/AMG التي قام بها موظفون من خارج الإدارة لضمان احتساب عمولات الإدارة أو مراجعة هوامش الأسعار.
8. **التنبيهات وقواعد العتبات (Smart Alerts Engine):**
   - قائمة تنبيهات مصنفة ومفلترة مع إمكانية ضبط عتبات الأيام (مثلاً: تنبيه قبل استحقاق الفاتورة بـ 3 أيام، أو عند ركود صنف لأكثر من 60 يوماً).
9. **أداة الاستكشاف والربط الحي لأودو (Phase 0 Odoo Discovery Engine):**
   - مدخلات الإعداد: URL الخادم (`https://www.eelaf.com/odoo`)، اسم القاعدة (`eelaf-master-21952014`)، اسم المستخدم / البريد (`tamereelaf@gmail.com`)، ومفتاح الـ API.
   - زر فحص الاتصال وقراءة إصدار الخادم والصلاحيات الممنوحة.
   - كاشف الحقول (Model Field Inspector): فحص نماذج `sale.order.line`, `account.move.line`, `product.template` لاكتشاف اسم حقل البراند الفعلي (مثل `x_brand`, `brand_id`, `product_tag_ids`).
   - حاسبة جودة البيانات (Brand Classification Health Meter): حساب نسبة البنود المصنفة براند مقابل غير المصنفة وقياس نسبة الفواتير المختلطة، مع زر لتصدير "تقرير المرحلة 0" الجاهز للمدير وIT.

### 5. خطوات التنفيذ المجدولة بعد الاعتماد

1. **إعداد البنية التحتية والخادم المحلي:**
   - تجهيز `server.ts` بمسارات الوكيل لـ Odoo RPC وتأمين قنوات الاتصال.
   - ضبط `index.html` و`metadata.json` بالعناوين والمعايير الرسمية لإدارة PHY BU.
2. **بناء مستودع البيانات ونموذج الحسابات:**
   - محرك تحويل العملات (USD / EGP) وحسابات الضريبة 14% بدقة على مستوى البنود.
   - قاعدة البيانات المدمجة للتوكيلات الثلاثة مع تتبع الفواتير المشتركة وأعمار المخزون.
3. **تطوير واجهات الوحدات التسع:**
   - لوحة القيادة والمؤشرات العليا.
   - شاشات التحصيلات، الموردين، الأوامر، المخزون، والعملاء.
   - وحدة الفريق والتنبيهات المبرمجة.
   - شاشة استكشاف Odoo للمرحلة 0 مع أداة اختبار الحقول وتقييم النقاء الإحصائي.
4. **الفحص والتحقق الكامل:**
   - فحص الأداء وتوافقية واجهة المستخدم والأجهزة، وإجراء `compile_applet`.
